## О продукте

Kagevi Subtitles превращает речь с микрофона в **живые субтитры** для OBS — с опциональным переводом, стилем, озвучкой и чтением Twitch-чата.

Всё работает **на вашем ПК**. Аккаунта Kagevi и облачного бэкенда нет. По умолчанию приложение слушает только `http://127.0.0.1:8765` (этот компьютер).

| Хотите… | Используйте… |
| --- | --- |
| Быстрый старт, распознавание Google в Chrome | **Web Speech** (по умолчанию) |
| Офлайн без окна Chrome | **Local ASR** (Parakeet / ONNX) |
| Субтитры в OBS | Browser Source → `/overlay` |
| Перевод (облако или без ключа) | вкладка **Перевод** (до 4 линий) |
| Озвучка субтитров | модуль **TTS** (нужен **Start** на Эфире) |
| Озвучка Twitch-чата | модуль **Twitch** (независимо от TTS субтитров) |
| Субтитры в Chatbox VRChat | модуль **VRChat** (OSC Chatbox) |
| Субтитры в шлеме PCVR | модуль **SteamVR HUD** (только для носителя) |

Текущая линия: **`0.7.0`** (первый релиз Kagevi — `0.5.0`). В этой линии: **VRChat Chatbox OSC**, **SteamVR HUD**, скорость прокрутки субтитров, сброс к заводским, полные снимки профилей и статус-бар Эфира на всех вкладках. Подробности: [список изменений](./CHANGELOG.md).

Программой можно пользоваться бесплатно. Copyright © 2026 Kiriuru. Все права защищены. Условия использования — в **[лицензии Kagevi Subtitles](../LICENSE)**.

> [!IMPORTANT]
> В OBS нужен именно: `http://127.0.0.1:8765/overlay`  
> После обновления приложения **перезагрузите** Browser Source, если overlay пустой или «залип».

### Системные требования

| Нужно | Зачем |
| --- | --- |
| Windows 10 или 11 (x64) | Поддерживаемая платформа |
| WebView2 Runtime | Окна приложения (на Win11 обычно уже есть; на Win10 установщик может поставить) |
| Google Chrome | Только для **Web Speech**. Для одного Local ASR не нужен |
| Микрофон | Разрешение в Chrome (Web Speech) или выбор в окне Local ASR |
| Интернет | Опционально для облачного перевода; также для первой загрузки моделей / runtime Local ASR |

Для запуска установленного приложения Python и Node.js не нужны.

### Установка и обновление

1. Запустите `Kagevi Subtitles_0.7.0_x64-setup.exe` (или свежий setup со [страницы релизов](https://github.com/kiriuru/Kagevi-Subtitles/releases)).
2. Откройте **Kagevi Subtitles.exe**.
3. Позже: на dashboard может появиться **баннер обновления**. **Установить обновление** скачивает подписанный NSIS (minisign), ставит его и перезапускает приложение. По-прежнему можно закрыть приложение и поставить новый setup поверх со страницы GitHub. Настройки в `user-data/` сохраняются.

Ручная ссылка **Скачать** / страница релиза остаётся, если не хотите ставить из приложения.

### Полезные локальные адреса

| Адрес | Что это |
| --- | --- |
| `http://127.0.0.1:8765/` | Главный dashboard |
| `http://127.0.0.1:8765/overlay` | Страница для OBS Browser Source |
| `http://127.0.0.1:8765/google-asr` | Chrome Web Speech worker |
| `http://127.0.0.1:8765/google-asr-compact` | Компактный Chrome `--app=` worker (опционально) |
| `http://127.0.0.1:8765/tts` | Окно модуля TTS (озвучка субтитров) |
| `http://127.0.0.1:8765/twitch` | Окно модуля Twitch (IRC + chat TTS) |
| `http://127.0.0.1:8765/local-asr` | Окно модуля Local ASR |
| `http://127.0.0.1:8765/vrchat` | Окно модуля VRChat Chatbox OSC |
| `http://127.0.0.1:8765/vr-overlay` | Окно модуля SteamVR HUD overlay |

## Быстрый старт

<p align="center">
  <img src="../Images/kagevi_live.png" alt="Вкладка Live" width="820"><br>
  <em><strong>Live</strong> — Start/Stop, статус распознавания, транскрипт, превью субтитров</em>
</p>

### Первый запуск под стрим (около 5 минут)

1. **Установите и запустите** Kagevi Subtitles.
2. В **OBS** добавьте **Browser Source**:
   - URL: `http://127.0.0.1:8765/overlay`
   - Размер — под ваш холст (или полный холст + crop).
3. На вкладке **Эфир / Live** выберите распознавание:
   - **Web Speech** (по умолчанию) — при Start откроется Chrome.
   - **Local ASR** — появится только после настройки модуля (см. [Local ASR](#local-asr)).
4. По желанию: **Перевод** — включите перевод, активируйте хотя бы одну линию, выберите провайдера (три работают **без API key** — ниже).
5. По желанию: **Субтитры** / **Стиль** — пресет, TTL, шрифты, цвета, **Прокручивание субтитров** и **скорость прокрутки**.
6. Нажмите **Start**. Статус-бар (ASR / WebSocket / Worker / OBS CC + Старт / Стоп) остаётся на **всех** вкладках — полный на Эфире, сжатый на остальных.
7. Говорите — смотрите превью на Live, затем OBS.
8. По желанию **VRChat**: [VRChat-модуль](#vrchat-модуль) — OSC вкл. → **Включить вывод** → **Start** на Эфире.
9. По желанию **PCVR**: [SteamVR HUD](#steamvr-hud-модуль) — **Запустить SteamVR** в верхней карточке модуля → **Включить оверлей субтитров** и/или **Включить чат-оверлей** → **Start** на Эфире (субтитры). Quest standalone этот overlay не показывает.

### Start и Stop простым языком

| Кнопка | Что происходит |
| --- | --- |
| **Start** | Запускает распознавание, перевод (если включён) и опциональные Closed Captions. Берёт **текущие** настройки с экрана, даже если вы ещё не нажимали Save. |
| **Stop** | Останавливает распознавание. Для Web Speech закрывается окно Chrome. Состояние субтитров сбрасывается. |

### Превью на Live

До Start показывается пример текста — удобно настроить стиль. После Start — то, что должно уходить в OBS. Одно только сохранение настроек в idle не «стирает» превью.

### Компактное окно

Компактный layout — высокое «телефонное» окно на второй монитор (**Настройки** → Layout или `Ctrl+K`). Live остаётся в фокусе, остальное — в один тап. Тот же статус-бар (полный на Эфире, сжатый на остальных) остаётся сверху.

## Выбор распознавания

<a id="выбор-распознавания"></a>

Одновременно нужен только **один** путь.

| | Web Speech (по умолчанию) | Local ASR |
| --- | --- | --- |
| Движок | Google Chrome Web Speech | Parakeet на вашем ПК (ONNX) |
| Окно Chrome | Да — держите открытым на стриме | Нет |
| Интернет для распознавания | Обычно да (Google) | Нет (после скачивания моделей) |
| Когда удобнее | Знакомый путь через Chrome | Офлайн / без worker-окна |
| Настройка | Разрешение mic в Chrome | Modules → Local ASR до статуса **ready** |

> [!TIP]
> Новичкам: начните с **Web Speech**. На Local ASR переключитесь позже, если нужен офлайн.

## Диагностика

> [!TIP]
> Идите по порядку: **нажали Start?** → **распознавание живое?** → **перевод включён?** → **URL в OBS верный?**

### Нет субтитров нигде

- [ ] На Live нажат **Start**?
- [ ] **Web Speech:** окно Chrome `/google-asr` открыто? Микрофон разрешён **в Chrome**? Лучше не сворачивать его надолго (может лежать под OBS/игрой).
- [ ] **Local ASR:** на Live выбран Local ASR? В Modules → Local ASR статус **ready**? Mic выбран там?
- [ ] Откройте **Ещё → Инструменты и данные** и посмотрите статус runtime / распознавания.

### Исходный текст есть, перевода нет

- [ ] Вкладка **Перевод** → перевод включён.
- [ ] Включена хотя бы одна линия перевода.
- [ ] Провайдеру нужен ключ? Добавьте в настройках провайдера. Или возьмите **безключевой**: Google Web, Free Web Translate, Bing Translator.
- [ ] Смотрите блок результатов / ошибок на той же вкладке — задержка иногда значит, что новая фраза отменила старый запрос (это нормально).

### В OBS пусто

- [ ] URL Browser Source заканчивается на `/overlay`, а не на `/` (это dashboard).
- [ ] **Субтитры**: исходник и/или переводы видимы.
- [ ] TTL не слишком короткий (текст может исчезнуть раньше, чем вы заметите).
- [ ] После обновления приложения: ПКМ по источнику → **Refresh**.
- [ ] Короткие обрывы связи: overlay часто держит последний кадр, пока переподключается — ожидаемо.

### Текст обрезается по краю источника OBS

После обновления перезагрузите Browser Source. Галочка **«Прокручивание субтитров»** (вкладка Субтитры, по умолчанию вкл.) оставляет крупный шрифт; каждая линия (исходник и переводы) медленно прокручивается в своём слоте. **Скорость прокрутки** (по умолчанию 48 px/с, диапазон 12–120) — на той же вкладке. Снимите галочку, чтобы обрезать по краям.

### На Live нет режима Local ASR

Доведите **Modules → Local ASR** до ready (зависимости + модель + warm load). CPU достаточно; CUDA опционален.

### В Chatbox VRChat пусто / не обновляется

Нужен **VRChat на этом ПК Windows** с включённым OSC. Quest standalone OSC для этого приложения не отдаёт.

1. В VRChat: **Action Menu → OSC → Enable**
2. **Модули → VRChat → Открыть**
3. **Проверить соединение** (OSCQuery / порт приёма **9001**) и **Отправить тест** (отправка в Chatbox, порт **9000**)
4. **Включить вывод**, затем **Start** на Эфире — live-фразы не уходят, пока Эфир не запущен
5. Окно модуля можно закрыть; вывод идёт, пока модуль включён

Если **Отправить тест** виден в Chatbox, а Live нет: не нажат Start, или **Что отправлять** указывает на выключенную линию перевода. Пауза по муту/AFK читает OSCQuery на localhost; отправка в Chatbox на 9000 может работать и без входящих пакетов.

### Google Web / keyless-перевод отвечает HTTP 429

Keyless web-провайдеры по умолчанию получают паузу между HTTP-вызовами. Общий лимит параллельных задач в **Настройках** действует на всех провайдеров; для Google Web / Free Web / Bing там же можно добавить потолок по имени. Подождите, включите меньше линий перевода, переключитесь на **Free Web Translate** или **Bing Translator**, либо измените интервал. Пустой `provider_limits` в конфиге при save не переписывается — runtime всё равно применяет интервал.

### HUD SteamVR не виден (PCVR)

Нужны **Steam + SteamVR** на этом ПК. Quest standalone overlay не показывает.

1. **Модули → SteamVR HUD → Открыть**
2. Нажмите **Запустить SteamVR** в **верхней карточке статуса** (не в чеклисте ниже)
3. Дождитесь бейджа **Включён**, а не **Ожидание SteamVR**
4. Настройте точку крепления, пресеты запястья и **Что показывать**
5. Нажмите **Включить оверлей субтитров** и/или **Включить чат-оверлей**, затем **Start** на Эфире (субтитры)
6. Закройте окно модуля — HUD работает, пока запущены SteamVR и сессия ядра
7. По желанию: **Отправить тест** в секции SteamVR — если тестовый кадр виден, позиция в порядке, а live-субтитрам нужен **Start**

Если вы сами вышли из SteamVR (рабочий стол или шлем), запустите его снова из модуля. HUD **никогда** не поднимает SteamVR сам.

Ноутбук / две видеокарты: оставьте SteamVR на GPU, которая кормит шлем. HUD берёт тот же адаптер.

### Квадраты вместо запятых / букв в SteamVR HUD

HUD рисует свои пиксели (это не браузер). Пустые рамки раньше были у японских `、。`, польских / турецких / вьетнамских букв и цифр рядом с тайским. В текущих сборках — полный Noto Sans, CJK / арабица / хинди / тайский и фолбэк на Segoe UI в Windows.

- Обновитесь до актуального `0.7.0` (или новее).
- **Отправить тест** со строкой, где есть эти символы.
- OBS `/overlay` здесь ни при чём — Chrome и так подставляет системные шрифты.

### Worker постоянно падает (Web Speech)

- Нестабильная сеть до endpoints Google Speech.
- **Stop → Start** или перезапуск worker из инструментов.
- Для бага: `VOICESUB_TRACE_BROWSER=1` → `logs/browser-trace.jsonl`.

### Текст «залип» после Stop / истечения TTL

Обновите сборку и **обновите** Browser Source в OBS. Старый билд иногда не чистит пустой кадр.

## Где что лежит

<a id="где-что-лежит"></a>

Основные разделы (левая / нижняя навигация):

| Место | Что делаете |
| --- | --- |
| **Эфир (Live)** | Start/Stop, режим распознавания, **статус-бар** (полный KPI здесь), транскрипт, превью |
| **Перевод** | Провайдеры, до 4 линий, кэш, опции realtime |
| **Субтитры** | Раскладка overlay, **Прокручивание субтитров** + скорость, видимость, порядок, время жизни строк |
| **OBS** | Скопировать URL overlay; опциональные Closed Captions |
| **Модули** | Компактные квадратные карточки (иконка / статус / Открыть / **?**) для **TTS**, **Twitch**, **Local ASR**, **VRChat** и **SteamVR HUD** |
| **Ещё** | Тема, замена слов, инструменты, настройки (включая сброс к заводским), справка |

**Command palette** (`Ctrl+K` или поиск в шапке): прыжок к панели, Start/Stop, Save, экспорт diagnostics.

## Browser Speech (Web Speech)

<p align="center">
  <img src="../Images/kagevi_webWorker.png" alt="Web Speech worker" width="820"><br>
  <em><strong>Web Speech worker</strong> — окно Chrome на <code>/google-asr</code> (держите открытым, пока слушаете)</em>
</p>

<p align="center">
  <img src="../Images/kagevi_webWorker_compact.png" alt="Компактный Web Speech worker" width="520"><br>
  <em><strong>Компактный worker</strong> — опциональное окно Chrome <code>/google-asr-compact</code> <code>--app=</code></em>
</p>

### Как это выглядит каждый день

1. На Live оставьте распознавание **Web Speech** (browser Google).
2. Нажмите **Start** — откроется отдельное окно Chrome со страницей worker.
3. Разрешите микрофон **в этом окне Chrome**.
4. Не закрывайте окно на стриме (может лежать под OBS/игрой). Закрытие = стоп распознавания.

Список микрофонов в главном dashboard пустой специально — mic выбирается в Chrome, не в настройках Kagevi.

### Правила окна worker (важно)

- **Полный worker** (по умолчанию): **обычное окно Chrome** с адресной строкой (не скрытая вкладка).
- **Компактный worker** (опционально): галочка на вкладке Эфир открывает `/google-asr-compact` в меньшем Chrome `--app=` (без omnibox). Тот же изолированный профиль и путь распознавания.
- Отдельный профиль Chrome в `user-data/`, чтобы не мешать вашему повседневному браузеру.
- На Windows Chrome реже «засыпает» вкладку во время стрима.

### Язык распознавания

Задайте язык речи в **Настройках** (Web Speech / язык распознавания). Совпадайте с тем, на каком говорите. В окне worker виден живой текст — если слова там есть, а на Live нет, проблема не в Chrome (перезапустите сессию).

<details>
<summary><strong>Advanced Web Speech (по желанию)</strong></summary>

<p align="center">
  <img src="../Images/kagevi_settings_web_speech_advenced.png" alt="Advanced Web Speech" width="820"><br>
  <em><strong>Advanced Web Speech</strong> — forced final, reconnect, ротация сессии</em>
</p>

**Настройки → Advanced Web Speech** — forced final, паузы перезапуска, длина сессии и соседние параметры. У каждого поля есть подсказка **`!`**.

После крупных правок: **Save → Stop → Start**, при необходимости заново откройте worker.

Idle-таймаут forced final правится в самом **окне worker** (`force_finalization_timeout_ms`), не только в Advanced.

Старые имена вроде `pause_to_finalize_ms` / `hard_max_phrase_ms` в рантайме не работают — не трогайте их вручную.

</details>

<details>
<summary><strong>Стабильность</strong></summary>

- Сессия Chrome по умолчанию ротируется примерно раз в 3 минуты.
- После длинной финальной фразы (≥200 символов) worker обновляет внутренний буфер — следующие фразы чище.
- Wake Lock может не давать ПК уснуть, пока идёт распознавание.

</details>

## Local ASR

Офлайн-распознавание на вашем ПК (Parakeet + ONNX). Без окна Chrome, пока на Live выбран этот режим.

<p align="center">
  <img src="../Images/kagevi_modules_main.png" alt="Модули" width="400">
  &nbsp;
  <img src="../Images/kagevi_localASR_1.png" alt="Модуль Local ASR" width="400"><br>
  <em><strong>Модули</strong> / <strong>Local ASR</strong> — откройте модуль и доведите setup</em>
</p>

<p align="center">
  <img src="../Images/kagevi_localASR_setup.png" alt="Настройка Local ASR" width="720"><br>
  <em><strong>Setup</strong> — скачать ORT / опционально CUDA и модель Parakeet</em>
</p>

<p align="center">
  <img src="../Images/kagevi_localASR_2.png" alt="Test bench Local ASR" width="720"><br>
  <em><strong>Local ASR</strong> — realtime-опции, inference и mic test bench</em>
</p>

### Один раз настроить

1. Откройте **Модули → Local ASR** (отдельное окно).
2. Пройдите чеклист: проверить/скачать runtime → скачать модель → warm-load → выбрать mic → короткий тест до появления final-текста.
3. Когда модуль **ready**, окно можно закрыть — настройки в `user-data/modules/local-asr/`.
4. На **Live** выберите **Local ASR** и нажмите **Start**.

Для Live хватает CPU. CUDA опционален (быстрее на подходящих NVIDIA после доп. загрузок). Для CUDA берите модели **fp16** или **fp32** — **int8** остаётся на CPU.

На чистой установке warm-load можно запускать **в той же сессии** сразу после скачивания ORT/CUDA (для обычного первого setup перезапуск приложения не нужен).

### После смены VAD / realtime

На Live сделайте **Stop → Start**, чтобы новые настройки микрофона/пайплайна применились.

### Что получаете

Тот же путь субтитров, перевода, стиля и OBS, что у Web Speech — меняется только движок речи.

## Перевод

<p align="center">
  <img src="../Images/kagevi_translation.png" alt="Вкладка Перевод" width="820"><br>
  <em><strong>Перевод</strong> — включить пайплайн, выбрать провайдеров, до 4 линий</em>
</p>

<p align="center">
  <img src="../Images/kagevi_translation_provider_settings.png" alt="Настройки провайдера перевода" width="820"><br>
  <em><strong>Настройки провайдера</strong> — API-ключи, endpoint и опции конкретного движка</em>
</p>

### Простая настройка

1. Включите **перевод**.
2. Включите одну или несколько линий (`translation_1` … `translation_4`).
3. Для каждой линии — язык и провайдер.
4. Save (или сразу Start — Start тоже берёт текущий снимок UI).

ASR работает и без перевода (только исходник).

### Линии

Каждая линия независима: вкл/выкл, язык, провайдер, короткая метка. Больше активных линий — больше нагрузки на провайдеров. Порядок на экране задаётся во вкладке **Субтитры**.

### Провайдеры без API key

Удобный старт без аккаунтов:

| Провайдер | Заметки |
| --- | --- |
| **Google Web** | Бесплатный путь Translate Element. При **HTTP 429** — пауза, меньше линий или лимиты в Настройках |
| **Free Web Translate** | Отдельный бесплатный путь Google (свои лимиты) |
| **Bing Translator** | Keyless Bing web session (`ttranslatev3`) |

Всего **17** провайдеров (Google API, DeepL, Azure, LibreTranslate, OpenAI-compatible, китайские и др.). Ключи хранятся только в локальном `config.toml`. Старые конфиги с `microsoft_edge` или `public_libretranslate_mirror` при load/save мигрируют на **Bing Translator**.

### Кэш

Память и опциональный диск (`user-data/translation-cache/`) не дергают провайдера повторно на тот же текст. Если часто меняете промпты LLM — учитывайте старый кэш, пока текст не изменится.

### Опциональный realtime-перевод

По умолчанию выкл. Для классических MT можно показывать черновики перевода, пока фраза ещё растёт. LLM-провайдеры ждут finals. Удобно для «живой» картинки; если нужна только стабильная строка — оставьте выкл.

### Поведение на экране

Завершённый блок субтитров **остаётся**, пока не завершится **следующая** фраза. Поздние переводы могут долететь. Если новая фраза отменила старый запрос — это защита от устаревшего текста, а не случайный сбой.

## Субтитры

<p align="center">
  <img src="../Images/kagevi_subtitles.png" alt="Вкладка Субтитры" width="820"><br>
  <em><strong>Субтитры</strong> — пресет раскладки, видимость, порядок, время жизни строк</em>
</p>

| Настройка | Простыми словами |
| --- | --- |
| Пресет overlay | Как складываются ряды: **single**, **dual-line** или **stacked**. Компактные отступы — отдельный переключатель. URL OBS может переопределить `?preset=…&compact=1`. |
| Прокручивание субтитров | По умолчанию вкл. (`overlay.fit_to_box`). Крупный шрифт; каждая линия прокручивается внутри Browser Source, если не влезает. `?fit=0` отключает для одного источника. |
| Скорость прокрутки | По умолчанию **48** px/с (диапазон **12–120**). Как быстро ползут длинные строки при включённом прокручивании. |
| Видимость | Показывать исходник и переводы. Сколько линий перевода на экране — по **включённым** линиям в Переводе (отдельного «максимума строк» нет). |
| TTL / время жизни | Как долго держать законченную строку после паузы. |
| Порядок линий | Для превью, OBS overlay и режима Closed Captions «первая видимая линия». |

> [!IMPORTANT]
> Пока начинается новая фраза, предыдущий готовый перевод может оставаться, пока новая фраза не **финализируется**. Так экран читается в естественных паузах.

## OBS

<p align="center">
  <img src="../Images/kagevi_obs_1.png" alt="Вкладка OBS" width="820"><br>
  <em><strong>OBS</strong> — URL overlay и опциональные Closed Captions</em>
</p>

<p align="center">
  <img src="../Images/kagevi_obs_2.png" alt="Доп. Closed Captions OBS" width="820"><br>
  <em><strong>Closed Captions extras</strong> — debug text source, partials и интервалы отправки</em>
</p>

### Overlay (то, что нужно большинству)

1. Скопируйте URL со вкладки **OBS** (по умолчанию `http://127.0.0.1:8765/overlay`).
2. Вставьте в OBS **Browser Source**.
3. Держите Kagevi запущенным на стриме.

Overlay **держит крупный шрифт** внутри Browser Source (например 800×600). Субтитры сидят **сверху** и растут **вниз**. Если линия (исходник или перевод) выше своей доли окна, **прокручивается только она**. Включается на вкладке **Субтитры**: *Прокручивание субтитров*. Скорость — **Скорость прокрутки** на той же вкладке.

Опционально в URL: `?preset=stacked&compact=1`. `?fit=0` отключает автоподгонку только для этого источника. Обычно проще менять пресет в приложении, а не только в OBS.

### Closed Captions (опционально)

Отправка captions в OBS через WebSocket (удобно платформам с CC, например Twitch).

- Включите на вкладке OBS; host / port / password как в OBS WebSocket v5.
- Что слать: live source, только finals, линия перевода (`translation_1`…`translation_4`) или первая видимая линия.
- Опционально: **live-partial переводы** в режимах `translation_*` (`send_translation_partials`; throttle как у source). Finals остаются для LLM / провайдеров без partials.
- Нативные stream captions работают только пока OBS реально стримит.
- Twitch native CC надёжен для **латиницы**; кириллица / CJK обычно через **browser overlay**.
- Debug mirror может писать в текстовый источник OBS для проверки.

## Замена слов

<p align="center">
  <img src="../Images/kagevi_word_replace.png" alt="Вкладка Замена слов" width="820"><br>
  <em><strong>Замена слов</strong> — правка ошибок ASR до перевода и показа</em>
</p>

Чистит имена, сленг и ослышки **до** перевода и overlay.

- Свои пары find/replace.
- Опциональные builtin-списки / стемы (en/ru/ja/ko/zh) и лёгкая нормализация обходов.
- Маска builtin / пустой замены: видны **первая и последняя** буква (`fuck`→`f**k`, `whore`→`w***e`); уже замаскированные формы с `*` не переписываются.
- Регистр; **whole-word** для своих пар. Builtin латиница/кириллица всегда по целому слову (чтобы `бля` не портил `кораблями`); Hangul — по пробелам; CJK multi-char — substring, одиночные иероглифы и короткая катакана — только изолированно.

У Twitch chat TTS в окне модуля **Twitch** свои фильтры (то же правило маски); пары замены слов с dashboard туда сами не применяются.

## TTS-модуль

<p align="center">
  <img src="../Images/kagevi_tts_1.png" alt="Модуль TTS" width="820"><br>
  <em><strong>TTS</strong> — озвучка субтитров</em>
</p>

Открывается из **Модули → TTS** (`/tts`). Настройки в `user-data/modules/tts/`. Окно можно закрыть — воспроизведение продолжается, пока модуль включён.

Озвучка субтитров требует **Start** на Эфире (в отличие от IRC Twitch, который может работать без Live).

### Озвучка субтитров

- Включите speech-канал, выберите голос / скорость / громкость.
- Громкость до **150%**.
- Режимы playback:
  - **Native** — минимальная задержка, скорость 1.0×
  - **Sonic** — менять скорость речи с сохранением высоты тона
- Движок TTS: **Google HTTP proxy** (`browser_google`) или **Python sidecar** (`python_stdlib` через встроенный `google_tts_fetch.exe`).
- Отдельное устройство вывода для озвучки субтитров (независимо от chat TTS Twitch).

Проверка без Live — кнопка Speak / sample в модуле.

Вспомогательный бинарник Google TTS уже лежит в runtime модуля — отдельно ставить Python не нужно.

## Twitch-модуль

<p align="center">
  <img src="../Images/kagevi_tts_twitch_1.png" alt="Модуль Twitch" width="820"><br>
  <em><strong>Twitch</strong> — лог IRC-чата и опциональная озвучка (до пяти каналов)</em>
</p>

<p align="center">
  <img src="../Images/kagevi_tts_twitch_connection.png" alt="Подключение Twitch" width="820"><br>
  <em><strong>Подключение Twitch</strong> — OAuth вещателя, каналы и EventSub-алерты</em>
</p>

<p align="center">
  <img src="../Images/kagevi_tts_twitch_2.png" alt="Фильтры Twitch" width="820"><br>
  <em><strong>Фильтры Twitch</strong> — emotes, язык, шаблон озвучки, замена ников</em>
</p>

Открывается из **Модули → Twitch** (`/twitch`). Настройки в `user-data/modules/twitch/`. Enable-without-window: закрытие webview **не** рвёт IRC и не глушит chat TTS.

Озвучка чата **независима** от TTS субтитров — можно использовать одно, оба или ни одного.

### Подключение и каналы

1. **Подключиться к Twitch** — как в Streamer.bot: токена **Broadcaster** достаточно (`chat:read` + скоупы EventSub). Он сам подключает чат стримера и помечает канал как **Broadcaster**. Токен **бота** (`chat:read`) необязателен — отдельный IRC-логин / доп. каналы. OAuth в системном браузере. Redirect URI по-прежнему `http://localhost:{port}/tts`; неаутентифицированная страница `/tts` — OAuth shell.
2. Доп. логины каналов (без `#`) **необязательны** (всего до **5** JOIN, включая авто-канал стримера). Сторонние каналы — **только чат**.
3. Включите **Озвучивать сообщения чата**, чтобы читать отфильтрованные сообщения вслух.
4. Включите **Озвучивать события канала** и отредактируйте шаблоны фоллоу / саб / ресаб / гифт / рейд / чир. Алерты читаются **только на канале стримера (Broadcaster)**. EventSub идёт с аккаунта стримера; сабы/рейды/чиры также приходят из IRC как запасной путь на том же канале.
5. При обрыве IRC модуль пытается переподключиться; ошибка auth останавливает цикл.
6. **?** у ника бота объясняет необязательный IRC-логин для доп. JOIN.

При старте приложения, если модуль включён и есть Broadcaster или бот, IRC **подключается сам** (без **Start** на Эфире).

### Движок и playback chat TTS

- **Движок TTS:** Google HTTP proxy (`browser_google`) или Python sidecar (`python_stdlib`) — отдельно от настроек субтитрового TTS.
- **Режим playback:** Native или Sonic (как в модуле TTS).
- **Устройство вывода**, громкость и скорость для озвучки чата/событий настраиваются здесь (независимо от TTS субтитров; скорость действует в режиме Sonic).
- **Тестовая фраза** и **Очистить очередь** — проверка звука без ожидания чата.

Фильтры (emotes, ссылки, символы, язык, маска мата) применяются сразу — обычно без reconnect.

## VRChat-модуль

<p align="center">
  <img src="../Images/kagevi_vrchat_1.png" alt="Модуль VRChat" width="820"><br>
  <em><strong>VRChat</strong> — OSC Chatbox для социальных субтитров в VR</em>
</p>

Опциональный **социальный** вывод: текст пайплайна в **Chatbox** VRChat по OSC. Его видят другие игроки в инстансе. Это **не** HUD в шлеме и **не** KAT — субтитры только для себя в SteamVR даёт [SteamVR HUD](#steamvr-hud-модуль).

Открывается из **Модули → VRChat**. Тема, язык интерфейса и шрифт UI совпадают с дашбордом. Настройки: `user-data/modules/vrchat/config.toml` (создаётся при первом открытии). Профили и **Сброс к заводским** включают этот файл.

### Требования VRChat

- **VRChat на этом ПК Windows** (PCVR или десктоп). Quest standalone OSC для Kagevi не отдаёт.
- OSC **включён** в VRChat (**Action Menu → OSC**)
- На Эфире **Start** для live-субтитров (**Отправить тест** / **Проверить соединение** работают без Live)
- Лимит Chatbox: **144 символа / 9 строк**, UTF-8 (японский, русский и другие скрипты, которые VRChat уже показывает)

Оставайтесь на `127.0.0.1`. Слушатель только loopback — Windows не должен спрашивать доступ к локальной сети от чужого имени процесса.

### Настройка Chatbox

1. Запустите VRChat и включите **OSC**
2. **Модули → VRChat**
3. Хост `127.0.0.1`, порт отправки **9000**, порт приёма **9001** (должен совпадать с портом отправки OSC в VRChat)
4. [Что слать в Chatbox](#что-слать-в-chatbox) и [опции Chatbox](#опции-chatbox)
5. **Проверить соединение**, затем **Отправить тест** — тестовая строка должна появиться в Chatbox
6. **Включить вывод**
7. **Start** на Эфире
8. Закройте окно модуля — Chatbox обновляется, пока `enabled` и Live запущен

Бейджи карточки **Модули**: **Выкл** / **Включён** / **Muted** / **AFK** (+ выбранный слой).

### Порты OSC

| Направление | По умолчанию | Для чего |
| --- | --- | --- |
| Приложение → VRChat | `127.0.0.1:9000` | Текст Chatbox (`/chatbox/input`) |
| VRChat → приложение | `127.0.0.1:9001` | **Проверить соединение** и опциональная пауза по муту / AFK |

**Проверить соединение** ищет OSCQuery VRChat на localhost (`/?HOST_INFO`) и может ждать UDP на порту приёма. Сообщение вроде «OSC VRChat включён (OSCQuery)» значит, что OSC жив; отправка в Chatbox на **9000** **не** ждёт входящих пакетов.

**Отправить тест** сразу пишет в Chatbox (обходит «Включить вывод» и Live). Так проверяют порт отправки до Эфира.

Звука уведомления Chatbox в UI нет. В OSC-пакете аргумент SFX всегда выключен (VRChat этот флаг часто игнорирует).

### Что слать в Chatbox

Та же идея, что у OBS Closed Captions. Линии перевода в списке — только **включённые** на вкладке Перевод (подписи вроде `Source · ja`, `Translation 1 · en`). Пока окно открыто, список обновляется примерно раз в 2 с.

| Содержимое | Смысл |
| --- | --- |
| **Источник** | Распознанный текст (язык показывается, если распознавание не `auto`) |
| **Перевод 1–4** | Этот слот перевода — только если линия включена |
| **Первая видимая строка** | Первая строка, которая сейчас видна в payload overlay |
| **Оригинал + перевод 1** | Оба, друг под другом (всё равно clamp 144 / 9 строк) |
| **Свой шаблон** | Плейсхолдеры `{source}`, `{tr1}`, `{tr2}`, `{tr3}`, `{tr4}` |

Если выбрать линию перевода, а потом выключить её на вкладке Перевод, в списке она останется помеченной как неактивная, пока не выберете другой режим.

### Опции Chatbox

| Опция | По умолчанию | Смысл |
| --- | --- | --- |
| **Только финальные сегменты** | вкл. | Не слать live-partials; ждать готовую фразу |
| **Не слать неизменённый текст** | вкл. | Не повторять ту же строку |
| **Не слать текст, пока я в муте** | выкл. | Пауза при **MuteSelf** в VRChat (нужен OSCQuery) |
| **Не слать текст, пока я AFK** | выкл. | Пауза при **AFK** в VRChat (нужен OSCQuery) |
| **Макс. символов** | **144** | Clamp 1–144 |
| **Мин. интервал (мс)** | **1000** | 200–10000. Если фразы чаще — уходит только **последняя** |
| **Очистить Chatbox через (мс)** | **5000** | Пустой Chatbox по таймеру. **0** = до следующей фразы. Иначе 500–60000. Новая отправка отменяет предыдущий таймер. После автоочистки ту же completed-фразу повторно не шлём, пока не сменится текст |

Мут / AFK опрашиваются из OSCQuery примерно два раза в секунду (одних UDP change-only пакетов мало). Включите вывод, сохраните настройки и держите OSC в VRChat.

### Включить и закрыть окно

Настроили → **Включить вывод** → закрыли. Отправка идёт, пока Live запущен. Повторное открытие окна подхватывает `config.toml` и тему дашборда. **Выключить вывод** в модуле (или сброс к заводским) останавливает Chatbox.

Контракты (OSC, HTTP, ключи config): [Техническая архитектура §18b](./TECHNICAL_ARCHITECTURE.md#18b-модуль-vrchat-chatbox-osc).

## SteamVR HUD-модуль

<p align="center">
  <img src="../Images/kagevi_steamVR_1.png" alt="Модуль SteamVR HUD" width="820"><br>
  <em><strong>SteamVR HUD</strong> — окно модуля, размещение и что показывать</em>
</p>

<p align="center">
  <img src="../Images/kagevi_steamVR_2.png" alt="Настройки SteamVR HUD" width="820"><br>
  <em><strong>SteamVR HUD</strong> — пресеты canvas, шрифты и интервал submit</em>
</p>

<p align="center">
  <img src="../Images/kagevi_steamVR_chatOvly.png" alt="SteamVR HUD в шлеме" width="820"><br>
  <em><strong>SteamVR HUD</strong> — overlay только для носителя в PCVR (не попадает в OBS)</em>
</p>

Опциональный вывод **только для носителя**: те же строки, что в OBS, на quad OpenVR overlay внутри SteamVR. Видите **только вы** в шлеме. Зрители стрима по-прежнему смотрят OBS `/overlay`. Люди в VRChat — это отдельный [модуль Chatbox](#vrchat-модуль) на 144 символа, не HUD.

Открывается из **Модули → SteamVR HUD**. Настройки: `user-data/modules/vr-overlay/` (`config.toml`, плюс `openvr-host.pid` / `openvr-host.log` у хоста overlay). Тема, язык интерфейса и шрифт UI совпадают с дашбордом.

HUD **не** попадает в захват OBS. Он рисуется поверх игр SteamVR только для носителя.

### Требования

- PCVR на Windows со **Steam + SteamVR**
- **Не** Quest standalone (нет compositor SteamVR)
- На Эфире **Start** для live-субтитров (тестовый кадр можно без Live)
- Трекинг шлема при креплении **Headset**; трекинг контроллера — для левого/правого

### Настройка один раз

1. **Модули → SteamVR HUD**
2. **Запустить SteamVR** в **верхней карточке** (не в чеклисте)
3. Дождитесь **SteamVR connected** / бейджа **Включён** (или **Ожидание SteamVR**, пока runtime не поднимется)
4. [Размещение](#размещение), [что показывать](#что-показывать), пресет холста
5. **Сохранить настройки**, затем **Включить оверлей субтитров** и/или **Включить чат-оверлей**
6. По желанию: **Тестовое сообщение** → **Отправить тест** и посмотрите в шлем
7. **Start** на Эфире (нужен для субтитров; чат-оверлей Live не требует)
8. Закройте окно модуля — HUD работает, пока включён хотя бы один оверлей, SteamVR и сессия ядра живы

**Проверить SteamVR** только спрашивает, доступен ли overlay API. SteamVR он не запускает.

Бейджи карточки **Модули**: **Выкл** / **Ожидание SteamVR** / **Включён** (+ origin) / **Пауза**.

### Размещение

| Origin | Где панель |
| --- | --- |
| **Headset (HMD)** | По умолчанию перед глазами, чуть ниже. Следует за шлемом. |
| **Левый / правый контроллер** | Следует за контроллером. **Пресет запястья**: Wrist, Near, Far, Palm, над рукой, под рукой. |
| **Мир (absolute)** | Фиксирован в play space (голову не сопровождает). |

Поза (смещение, поворот, ширина) **запоминается отдельно** для каждого origin и пресета запястья. Переключение HMD → запястье → HMD возвращает последний сетап HMD, а не заводской.

- **Сбросить смещение** возвращает *текущий* origin к калиброванной базе (не все сразу).
- **Nudge** двигает шагами 1 мм / 5 мм / 1 см.
- Локальные оси OpenVR: **+X вправо, +Y вверх, −Z вперёд**. Дефолт HMD около `{0, -0.28, -1.15}` м.
- Не крутите панель на 180° по yaw — у overlay нет «обратной стороны», он исчезнет.
- Ширина по умолчанию **0.55 м** на HMD и **0.14 м** на контроллере. Непрозрачность и кривизна — по желанию.

### Что показывать

Галочки, не один выпадающий список — те же подписи, что в OBS / VRChat (`Source · ja`, `Translation 1 · en`, …). Видны только **включённые** линии перевода. У исходника показывается язык распознавания, если это не `auto`.

| Опция | Смысл |
| --- | --- |
| **Исходник** / **Перевод 1–4** | Какие линии пайплайна рисовать |
| **Только финалы** | Скрыть live-partials; ждать готовую фразу |
| **Мин. интервал отправки** | Как часто HUD перерисовывает растр (по умолчанию **90 мс**). Это не видео 90 FPS — SteamVR получает GPU-текстуру, когда меняется текст. |

Пустой кадр прячет панель (как OBS очищает пустой overlay).

### Экран (холст)

HUD — фиксированный пиксельный холст, в VR масштабируется в метрах.

| Пресет холста | Размер |
| --- | --- |
| **Default** | 1920×512 |
| **Tall** | 1920×768 |
| **Large** | 2560×720 |
| **Compact** | 1280×384 |
| **Custom** | Чётные ширина/высота, 256–2048 |

**Размер шрифта 0** = автоподгон под высоту холста и число строк. Попробуйте **36–48**, если в VR мелко; более высокий пресет лучше держит несколько линий.

### Языки и текст

HUD растеризует сам (fontdue + шейпинг). Это не веб-страница, поэтому отсутствующие глифы раньше были пустыми квадратами.

Текущие сборки покрывают языки перевода / ASR:

- японская / китайская пунктуация (`、。「」` и полноширинные `，！？`)
- корейский хангыль
- польский, турецкий, вьетнамский (расширенная латиница)
- русский и прочая кириллица
- арабица (связные формы, справа налево; латинские имена и `OBS` внутри фразы остаются слева направо)
- хинди (деванагари) и тайский (надстрочные знаки; ASCII-цифры остаются латинскими)

Перенос — по словам, где есть пробелы, и по кластерам для CJK. Японские закрывающие (`。、」`) не оставляются висеть в начале следующей строки.

### Старт и стоп SteamVR

| Кнопка | Что делает |
| --- | --- |
| **Запустить SteamVR** | Поднимает SteamVR (`vrstartup`, запасной `steam.exe -applaunch 250820`). **Только по кнопке** — модуль сам SteamVR не стартует. |
| **Остановить SteamVR** | Сначала снимает сессию overlay, затем просит SteamVR выйти (окно монитора, запасной console command). |

Если вы закрыли SteamVR из Steam или шлема, HUD переходит в **Ожидание SteamVR**. Когда снова понадобится — **Запустить SteamVR**. Между попытками реконнекта 5 с пауза, чтобы не долбить выключение.

OpenVR живёт в процессе `kageviSub-vr-overlay-host.exe`, чтобы зависший compositor не заморозил Live, VRChat и TTS. В диспетчере задач его можно не трогать; к баг-репорту приложите `user-data/modules/vr-overlay/openvr-host.log`.

### После закрытия окна

Включить и закрыть: настроили → **Включить оверлей субтитров** и/или **Включить чат-оверлей** → закрыли. Отправка кадров идёт, пока работает ядро. Профили и **Сброс к заводским** включают `config.toml` этого модуля. Повторное открытие окна подхватывает сохранённый файл и тему дашборда.

### Три выхода сравнение

| Выход | Кто видит | Как |
| --- | --- | --- |
| OBS `/overlay` | Зрители стрима | Browser Source |
| VRChat `/vrchat` | Люди в VRChat | OSC Chatbox (144 символа / 9 строк) |
| SteamVR `/vr-overlay` | **Носитель шлема** | OpenVR overlay (полные строки, только носитель) |

Контракты OpenVR / D3D11 / растеризации: [Technical Architecture §18c](./TECHNICAL_ARCHITECTURE.md#18c-модуль-steamvr-openvr-hud-overlay).

## Приватность и local-first

- По умолчанию приложение слушает только **localhost** (`127.0.0.1`). Другие устройства в LAN не достучатся.
- LAN bind (`VOICESUB_ALLOW_LAN=1`) — для advanced-сетапов: WebSocket тогда **без логина**, включайте только в доверенной сети.
- API-ключи перевода и токены Twitch остаются на диске.
- Diagnostics ZIP **редактирует** секреты перед экспортом.
- Chrome worker — изолированный профиль (не ваш обычный Chrome sync).

## Глоссарий

| Термин | Смысл |
| --- | --- |
| **Live / Эфир** | Главный экран Start/Stop и превью |
| **partial** | Текст ещё распознаётся (черновик) |
| **final** | Фраза завершена распознавателем |
| **линия / слот перевода** | Одна из до четырёх строк (`translation_1`…`translation_4`) |
| **overlay** | Страница `/overlay` для OBS |
| **Web Speech / browser worker** | Окно Chrome с Google Web Speech |
| **Local ASR** | Офлайн-модуль Parakeet |
| **completed block** | Готовый субтитр, пока не завершится следующая фраза |
| **TTS-модуль** | Отдельное окно озвучки финализированных субтитров (`/tts`) |
| **Twitch-модуль** | Лог IRC-чата + опциональная озвучка чата (`/twitch`), независимо от TTS субтитров |
| **VRChat-модуль** | OSC-вывод в Chatbox VRChat (социальный, 144 символа) |
| **SteamVR HUD** | OpenVR overlay для носителя шлема в PCVR (не OBS и не Chatbox VRChat) |
| **TTL** | Сколько держать готовую строку на экране |
