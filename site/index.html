How the product works

Wiki-style walkthrough of each major surface — recognition, translation, overlay, modules, and style.

Live — the control desk

Start and stop recognition, watch status chips, read the live transcript, and preview subtitle output before it hits OBS.

  • Start sends the current config snapshot (including unsaved edits).
  • Choose Web Speech or Local ASR when the module is ready.
  • Subtitle preview mirrors the OBS overlay payload shape.
  • Compact layout fits a secondary monitor or phone-style window.

Web Speech — Chrome worker

Production mode browser_google runs Google Chrome Web Speech in a separate window — full UI with address bar by default, or optional compact --app= from the Live tab.

  • Microphone permission is granted inside Chrome (getUserMedia).
  • Isolated worker profile under user-data; anti-throttling flags on Windows.
  • Recognition language and advanced restart / force-final options in Settings.
  • Don't minimize the worker window — it can stay behind other apps.

Local ASR — offline Parakeet

Optional sidecar module: Parakeet TDT via ONNX Runtime (CPU or CUDA). No Chrome worker when Live mode is local_parakeet.

  • Open Modules → Local ASR and finish setup until ready.
  • Lazy-download ORT, model weights, optional Silero VAD and CUDA redist.
  • Native mic capture (cpal) with WebRTC or Silero VAD.
  • Same subtitle / translation / overlay path as Web Speech after ingest.

Translation — up to four lines

Seventeen providers with queueing, cache, and stale-drop protection. ASR still works with translation turned off (source-only).

  • Up to four translation lines (source text is separate).
  • Keyless options: Google Web, Free Web Translate, Bing Translator.
  • Optional realtime translation — captions update while you speak, without waiting for the phrase to finish (off by default).
  • Memory/disk cache; late translations allowed; completed blocks stay until the next phrase finalizes.

Subtitles — overlay layout

Control which lines appear on the OBS overlay, their order, preset, and how long completed text remains visible.

  • Presets: single, dual-line, stacked + compact spacing (URL query overrides available).
  • Keep captions inside the OBS box (default): full-size font; each line scrolls when too tall (?fit=0 to clip).
  • TTL / lifecycle settings keep completed text stable during the next partial.
  • Reorder lines to control what appears first on the overlay.

OBS — Browser Source & CC

Primary output is a lightweight vanilla overlay page over WebSocket. Optional Closed Captions via OBS WebSocket are mainly for Twitch.

  • Add Browser Source → http://127.0.0.1:8765/overlay
  • Copy URL / open overlay helpers live on the OBS tab.
  • Closed Captions: meant for Twitch stream captions (other uses are uncommon).
  • After app updates, reload the Browser Source so fit-to-box / style assets refresh.

TTS — speech & Twitch chat

Sidecar module for subtitle speech and Twitch chat TTS with native or Sonic pitch-preserving playback.

  • Open from Modules → TTS (separate window, /tts).
  • Speak translated or source lines as they finalize.
  • Twitch chat TTS for up to five channels.
  • Audio devices and tempo are configured in the TTS module, not OBS.

Style — look of the captions

Fonts, colors, outline, shadow, backgrounds, and animated entrance effects — shared by dashboard preview and OBS overlay.

  • Built-in and custom presets; Save after edits.
  • Per-slot overrides for source and each translation line.
  • Effects: fade, slide-up, zoom, blur-in, glow, and more.
  • UI Theme (dark/light palette) styles the dashboard only — not the overlay.

Quick start

Four steps from installer to OBS captions.

  1. Install

    Run the Windows x64 setup from the latest GitHub Release.

  2. Launch

    Open Kagevi Subtitles — the dashboard opens in the main window.

  3. Add OBS source

    Browser Source → http://127.0.0.1:8765/overlay

  4. Start recognition

    Web Speech (don't minimize the Chrome worker) or Local ASR when the module is ready — then press Start.
